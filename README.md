## 🎯 The Mission

This repository documents my journey from JavaScript fundamentals to understanding how modern frontend frameworks work under the hood.

Instead of jumping straight into React, I'm building projects with **vanilla JavaScript** to understand the problems frameworks solve.

The goal isn't just to make things work. It's to understand why they work, where they break, and how to build them better.

> **The philosophy:** Learn a concept. Apply it. Understand its limitations. Then move forward.

## 🧠 What I'm Learning

These projects put JavaScript concepts into practice rather than treating them as isolated topics.

<details>
<summary><b>⚙️ JavaScript Fundamentals</b></summary>

* Variables, scope, and closures
* Prototype chain and inheritance
* The event loop: microtasks vs. macrotasks
* The `this` keyword and its binding rules
* `call()`, `apply()`, and `bind()`
* Execution context and function behavior

</details>

<details>
<summary><b>⚡ Asynchronous JavaScript</b></summary>

* Callbacks and callback hell
* Promises and promise chaining
* `Promise.all()`, `Promise.race()`, and other combinators
* `async/await` and error handling
* Fetch API
* `AbortController`
* Managing concurrent asynchronous tasks

</details>

<details>
<summary><b>🏗️ Object-Oriented Programming & Design Patterns</b></summary>

* Classes, inheritance, `extends`, and `super`
* Private class fields
* Custom error classes and error hierarchies
* Generators and iterators
* Observer Pattern
* Builder Pattern
* Mixin Pattern
* Proxy and Reflect
* Symbols

</details>

<details>
<summary><b>🌐 Browser APIs & Performance</b></summary>

* DOM manipulation and event delegation
* `localStorage` and `sessionStorage`
* Intersection Observer
* Debouncing and throttling
* Web Workers
* `requestAnimationFrame()`
* Memory leak prevention
* Clipboard API
* History API

</details>

<details>
<summary><b>🧩 Application Architecture</b></summary>

* Separation of concerns
* Module organization
* State management patterns
* Observer-based updates
* Component systems
* Virtual DOM and diffing
* Understanding the principles behind hooks

</details>

## 🌿 Git Workflow

I keep completed projects separate from active development.

```text
main
 └── Stable, completed projects

dev
 └── Active development and experimentation
```

My goal is to finish and test a project before merging it into `main`.

### Commit Convention

| Prefix      | Purpose                                         |
| ----------- | ----------------------------------------------- |
| `feat:`     | Add a new feature                               |
| `fix:`      | Fix a bug                                       |
| `docs:`     | Update documentation                            |
| `style:`    | Change formatting or CSS without changing logic |
| `refactor:` | Improve code structure                          |
| `perf:`     | Improve performance                             |
